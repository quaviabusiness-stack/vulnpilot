Run

Run

Vulnpilot is a free command-line tool under the MIT license. It needs Node.js 26 or later.

In CI, give the three CRA answers as flags and pick a failure threshold:

Prompts are skipped when --json or --non-interactive is used, CI is set, or stdin or stdout is not a terminal. In interactive mode the network lookups start before the questions, so they overlap.

Help

Help

Flags

Flags

Flag Meaning
--path <path> Project directory (lockfile auto-detected) or a specific lockfile. Default ..
--sbom <file> Scan a CycloneDX JSON SBOM instead of a lockfile.
--json Print the versioned JSON report to stdout; skips prompts.
--fail-on <level> critical, high or kev: exit 1 only for issues at that level. Default: any issue.
--offline Use only cached data (no network). Cached entries of any age are accepted.
--non-interactive Skip prompts; unanswered questions become unknown.
--eu-distribution <answer> Made available on the EU market? yes, no, unknown.
--commercial <answer> Supplied as part of a commercial activity? yes, no, unknown.
--product-type <type> app, library, firmware, saas, saas-with-client, unknown.
--no-color Plain output (NO_COLOR is also respected).
--no-telemetry Disable anonymous usage telemetry.
--version, --help Print the version or help.

Exit codes

Exit codes

Code Meaning
0 No issues, or none matching --fail-on.
1 Issues found (matching --fail-on if given).
2 Error: bad flags, no, unsupported or unparseable input, cancelled questions, or incomplete data. OSV could not be reached (or, with --fail-on kev, the KEV feed), so “no issues” cannot be claimed.

Issues already found still exit 1 even if a source failed. A missing EPSS score never changes the exit code.

Inputs

Inputs

Vulnpilot reads one file. The lockfile is auto-detected in --path. If none is found the CLI exits 2 and lists the supported names; if several exist it asks you to pick one.

Input Formats
package-lock.json lockfileVersion 1, 2, 3
pnpm-lock.yaml lockfileVersion 5.x, 6.x, 9.x (peer suffixes stripped)
yarn.lock Yarn Classic (v1) and Berry (v2+)
--sbom CycloneDX JSON, any spec version; nested components walked

Packages are deduplicated by ecosystem, name and version. Development and transitive dependencies are included. npm aliases (npm:real@x) resolve to the real package. Entries without an exact registry version (workspace, link: and file: packages, git and tarball dependencies, Yarn patches) are skipped and counted as skipped in the output.

SBOM components are matched by purl. Supported purl types: npm, pypi, maven, golang, cargo, gem, nuget, composer, hex, pub and conan map to OSV ecosystems; deb and apk purls are sent to OSV as purls. Components without a purl (for example CPE-only firmware parts) or with pkg:generic are skipped and counted.

Data sources

Data sources

Source What is sent Used for
OSV.dev POST /v1/querybatch Package ecosystem, name and exact version (or purl) Vulnerability IDs per package, up to 1,000 packages per request
OSV.dev GET /v1/vulns/{id} Advisory ID Summary, aliases (CVE IDs), CVSS, fixed versions
CISA KEV feed Nothing (full catalog download) “Actively exploited” flag for CVE aliases
FIRST EPSS API CVE IDs, up to 100 per request Exploit-likelihood score

Advisory details are fetched with at most 10 requests in flight. Every request has a timeout (10 s; 20 s for the KEV feed) and up to two retries with exponential backoff for network errors, timeouts, HTTP 429 and 5xx. Redirects are refused. If a source fails, the scan continues with the others and the report names the unavailable source; OSV being unavailable is never reported as “no vulnerabilities”.

The CLI reads only the lockfile or SBOM: no source code, manifests or file paths leave your machine. OSV does see the dependency names you query, including private package names.

Ranking

Ranking, severity and fixes

Ranking: actively exploited (KEV) first, then EPSS (highest first), then CVSS (highest first). The text output shows the top 10; --json contains all issues.

Severity: the CVSS v3.x base score is computed from the advisory’s vector. For advisories with only a CVSS v4 vector or none, the advisory’s own label (for example GitHub’s HIGH or MODERATE) is used and no numeric score is shown. Advisories for the same package that share an ID or alias are merged into one issue.

Fix version: the fixed version of the affected range that contains your installed version, falling back to the nearest higher fixed version.

CRA screen

CRA screen

Three questions, an ordered rule list, and the first matching rule decides. The verdict, the rule ID, the reason, the answers and the key dates are in every report. Not legal advice. Every rule is a draft marked for legal review. You can also answer the questions in your browser.

  1. Is the product made available on the EU market (sold, distributed or offered to users in the EU)?

    Yes (yes) · No (no) · Not sure (unknown)

  2. Is it supplied as part of a commercial activity (sold, licensed, monetised, or with paid support/services)?

    Yes (yes) · No (no) · Not sure (unknown)

  3. What kind of product is it?

    Installable software (desktop, mobile, CLI, on-prem server) (app) · Library or component that others integrate (library) · Firmware or a connected hardware device (firmware) · Pure SaaS / hosted service with nothing downloadable (saas) · SaaS with an app, desktop client, agent or firmware (saas-with-client) · Not sure (unknown)

Rule Condition Verdict
not-on-eu-market Not made available on the EU market likely_out_of_scope
pure-saas Pure SaaS, nothing downloadable likely_out_of_scope
non-commercial-open-source Not part of a commercial activity (mentions the open-source steward regime) likely_out_of_scope
commercial-eu-product EU market, commercial, and app, library or firmware likely_applies
saas-with-client SaaS with an app, desktop client, agent or firmware unclear
insufficient-information Anything else, for example any answer “not sure” unclear

Reporting obligations for actively exploited vulnerabilities and severe incidents apply from 11 September 2026 (early warning within 24 hours, then a notification within 72 hours and a final report once a fix or mitigation is available, including for products already on the market). Full obligations, including CE marking, apply from 11 December 2027. When the CRA likely applies and a KEV-listed vulnerability is found, the text output adds the line >>> Under the CRA, actively exploited vulnerabilities in your product must be reported within 24 hours.

The rules do not cover sectoral exclusions (medical devices, vehicles, aviation, marine, defence), importer or distributor roles, or important and critical product classes. Zero known vulnerabilities is not a security guarantee.

Cache

Cache and offline

Responses are cached for 24 hours in the OS cache directory: %LOCALAPPDATA%\vulnpilot\Cache on Windows, ~/Library/Caches/vulnpilot on macOS, $XDG_CACHE_HOME/vulnpilot (default ~/.cache/vulnpilot) elsewhere; override it with VULNPILOT_CACHE_DIR. Each cache file holds one OSV package result, OSV advisory, EPSS score or the trimmed KEV catalog.

Stale entries are refreshed online. --offline uses cached entries of any age and reports what is missing. If the KEV download fails, the last cached catalog is used and its date is shown.

Telemetry

Telemetry

Published builds send one anonymous event per completed scan, with exactly five coarse fields:

Field Value
cli_version The Vulnpilot version.
os Node’s platform (linux, darwin, win32, …) or other.
dep_count Number of scanned dependencies.
result_bucket The CRA verdict.
kev_count_bucket Actively exploited issues, bucketed as 0, 1, 2-5 or 6+.

No identifiers, package names, versions, paths, answers or vulnerability details are sent. Telemetry is off in CI (when CI is set), and --no-telemetry or VULNPILOT_TELEMETRY=0 turns it off. It never fails or slows a scan beyond a 1.5-second timeout.

JSON report

JSON report

--json prints a report validated against schema/report-v1.schema.json, which is shipped in the npm package. schemaVersion is 1.0.0; minor versions only add optional fields and a breaking change bumps the major version. Warnings about unavailable sources go to stderr, so stdout stays parseable. The waitlist line of the text output never appears in the JSON report.

Browser

Browser scanner

/scan runs the same parsers, sources, ranking and report code in your browser. It differs from the CLI in these ways:

  • Nothing is cached or stored, so there is no --offline and every scan fetches fresh data.
  • The KEV catalog comes from /api/kev on this site, a copy of the CISA feed trimmed to the fields Vulnpilot uses, because browsers cannot read the CISA feed directly.
  • Files are read up to 32 MB, and the report names the file, not a path.
  • The format is recognised from the file name as in the CLI, or from the content for pasted text and other names.
  • There is no exit code; the page shows the code the CLI would return.
