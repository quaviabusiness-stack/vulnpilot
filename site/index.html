Method

From lockfile to ranked report

Vulnpilot reads one file. Everything after that is a lookup against public data, joined and sorted on your machine.

CI

Fail the build on what is actually exploited

In CI, answer the three CRA questions with flags and choose a threshold. With --fail-on kev the job fails only when a dependency is in the CISA catalog, so a new medium-severity advisory does not block a release.

Exit codes

Code Meaning
0 No issues, or none at the --fail-on level.
1 Issues found.
2 Error or incomplete data. A scan that could not reach OSV never passes as clean.

--json prints a versioned report validated against a published JSON Schema, schema/report-v1.schema.json.

kev carries the CISA catalog entry, epss the score and the day it was published, and recommendedFix the version to upgrade to.

FAQ

Questions

Is this legal advice?

No. The CRA screen is a rule-based first pass from three answers: EU market, commercial activity and product type. It returns likely applies, likely out of scope or unclear, with the reason and the key dates. Ask a qualified adviser before you rely on it.

What leaves my machine?

Package names and versions, sent to OSV.dev. Vulnpilot reads only the lockfile or SBOM you point it at; source code, file paths and manifests stay local. Anonymous telemetry sends five coarse fields per scan, is off in CI, and --no-telemetry turns it off.

Why is the CLI free?

A scanner you can read is easier to trust. The code is MIT-licensed on GitHub and the CLI stays free. We plan to charge for monitoring and early-warning drafts, not for the scan.

What will the paid product cost?

Not decided yet. We’ll set scope and pricing with the first teams on the waitlist.

Which ecosystems are supported?

Lockfiles: package-lock.json (v1–3), pnpm-lock.yaml (5.x, 6.x, 9.x) and yarn.lock (Classic and Berry). Anything else through a CycloneDX JSON SBOM with --sbom, for purl types npm, pypi, maven, golang, cargo, gem, nuget, composer, hex, pub, conan, deb and apk.

Does it work offline or in CI?

Both. Responses are cached for 24 hours and --offline uses the cache only. In CI, pass --non-interactive with the three answers as flags, read the versioned --json report, and gate on exit codes with --fail-on critical|high|kev.
